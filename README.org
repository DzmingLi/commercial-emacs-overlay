#+title: commercial-emacs-overlay

Selected Commercial Emacs features ported to GNU Emacs 31: the complete
Gnus Lisp tree, native selected-window borders and GTK worker-thread wait
fixes. GNU Emacs remains the base editor.

* Source and license
The bundled source is from [[https://github.com/commercial-emacs/commercial-emacs][Commercial Emacs]], pinned to revision
=bf4184f985d0674a7c03c12eb33b66ac833d9e29=. See =UPSTREAM=, individual source
headers and =COPYING=. This distribution preserves upstream attribution.
The first commit imports upstream intact; GNU compatibility changes are a
separate commit.

* Installation with Nix
This repository exports =overlays.default=. It builds GNU Emacs 31 PGTK
with the complete built-in =lisp/gnus= tree replaced before autoload
generation and byte/native compilation, and applies the native C patches. There is no separate Lisp loader or competing Gnus package.

Add this flake input:

#+begin_src nix
inputs.commercial-emacs.url = "github:DzmingLi/commercial-emacs-overlay/v0.4.0";
#+end_src

Then select the editor from the overlay and derive packages from it:

#+begin_src nix
let
  commercialPkgs = pkgs.extend inputs.commercial-emacs.overlays.default;
  editor = commercialPkgs.emacs31-pgtk-commercial;
  epkgs = pkgs.emacsPackagesFor editor;
in epkgs.emacsWithPackages (epkgs: [ /* your other packages */ ])
#+end_src

For Home Manager, assign this editor or its wrapped result to
=programs.emacs.package=. Restart the daemon and graphical frames after
switching editors. Remove old =(require 'commercial-gnus)= calls and any
separate commercial-gnus Lisp package from your configuration.

The overlay deliberately exports a named editor instead of changing every
Emacs derivation in nixpkgs. It targets GNU Emacs 31; other versions require
reviewing the C patch against their sources.

* Native selected-window border
The overlay ports Commercial Emacs's =window-border-mode= into GNU Emacs
31 and adds a Cairo renderer for PGTK. It reserves space in window geometry
for the border, including headers, tab lines, scrolling and scroll bars.
This is a C redisplay feature; copying the Lisp file or hot-loading it into
an unpatched editor is insufficient.

#+begin_src emacs-lisp
(require 'window-border)
(setq window-border-width 2)
(window-border-mode 1)
#+end_src

Customize the =window-border= face to change its color. The global mode
can be enabled during daemon startup; minibuffer, pseudo windows and
terminal frames reserve no border. Disable the mode to restore normal
geometry. The overlay's PGTK build is tested; other graphical ports are
not advertised as supported.

Native regressions are in =tests/window-border-test.el=. Run the tests
with the built editor in both batch mode and an interactive PGTK frame;
the graphical geometry tests deliberately skip terminal frames. Actual
Cairo painting also requires visual inspection after switching windows,
scrolling, splitting and resizing.

* Background scanning
Use the normal Gnus commands, including =g= in Group. Upstream enables
=gnus-background-get-unread-articles= in interactive Emacs. Configure
ordinary Gnus activation levels and subscription state as usual.

The native scanner runs methods serially in an Emacs worker thread.
It does not promise concurrent requests across every backend. Synchronous
CPU work can still occupy the Lisp interpreter. Posting and fetching a
thread's replies are not automatically made asynchronous.

Views can adapt to native =gnus-group-update-group= and
=gnus-after-getting-new-news-hook=. There is no distribution-specific
notification interface. Consumers must schedule GUI updates on the main
thread and avoid recursive refreshes caused by their own group updates.

* GNU Emacs 31 GTK/PGTK patch
=patches/gnu-emacs31-glib-worker-wait.patch= keeps GLib/GTK event handling
on the main thread, following Commercial Emacs's C-level separation.
In a live unpatched PGTK session, a background scan coincided with a GLib
ownership assertion, a spinning worker and an unresponsive main thread.
Lisp-only batch tests do not exercise this GUI path.

The overlay applies this patch while building the editor. Lisp hot-loading
cannot apply a C patch. Non-Nix installations must replace the built-in
Gnus tree and apply this patch to GNU Emacs 31 sources before building.

* Compatibility and tests
GNU compatibility changes are separate from the upstream import and the
overlay packaging commit. They adapt Message's syntax cache hook, lazily
load Summary dependencies, declare compiler warning bindings, fix feed
parsing and generated RSS state headers, and honor foreign group methods
and activation levels. Conditional bindings use GNU Emacs 31's current
=when-let*= and =if-let*= macros.

Run =make check=. Tests include the real native scanner with a controlled
backend wait and a main-loop heartbeat.
An isolated live NixOS Discourse scan returned immediately and fetched 30
articles; it did not use personal credentials or modify personal newsrc.

Third-party backends continue to use standard Gnus methods. gnus-inbox must
make its custom Summary mark variables buffer-local without assuming GNU
Gnus's obsolete =gnus-summary-local-variables= registry exists.

For rollback, select the original nixpkgs editor and restart Emacs.
The overlay does not replace, rewrite or delete subscription files.

* Pending HTML images
=patches/gnu-emacs31-shr-stale-image.patch= prevents an image request from
writing into a document whose placeholder was erased during redisplay.
Downloaded images are still cached. This patch is independent of the GTK
worker wait fix and can also be applied without Commercial Gnus.
